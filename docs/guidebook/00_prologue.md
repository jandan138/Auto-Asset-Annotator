# 序章：赋予机器“视觉”的魔法

欢迎来到 **Auto-Asset-Annotator** 的世界。把这本手册当成一本冒险指南，我们要看的不是一个“还在想象中”的系统，而是一条已经跑通、已经交付过大规模结果的生产流程。

## 我们的任务：整理巨型仓库

想象一下，你接手了一个巨大的数字仓库。这里不是几百件，而是 **52,907** 个 3D 资产，每个资产都需要一份能落地使用的说明：

- 它是什么类别
- 长什么样
- 可能由什么材料构成
- 大概多大、多重
- 适合放在哪里

如果全靠人工，一个团队也要忙很久。于是我们请来一个既能看图、又能回答问题的帮手。

## 遇见“魔法大脑”：VLM

这个帮手叫 **VLM (Vision-Language Model，视觉-语言模型)**。

- 以前的视觉模型擅长“看出来是什么”
- 以前的语言模型擅长“把话说完整”
- VLM 把两者合在一起：看多张图，再按要求写出结构化回答

在这个项目里，主线模型是 **Qwen2.5-VL-7B-Instruct**。

## 什么是 Auto-Asset-Annotator？

如果说 VLM 是鉴定师，**Auto-Asset-Annotator** 就是整座鉴定中心。

它负责：

1. 自动扫描资产目录，找到真正要处理的资产
2. 为每个资产收集多视角图片
3. 组织 prompt，把图片和问题一并交给模型
4. 接收模型返回的 **structured text**
5. 把这些结构化文本解析成稳定的 JSON 文件

这里最关键的一点是：**系统不是直接相信模型吐出来的 JSON**。主线属性提取流程会先让模型输出带字段头的结构化文本，再由代码解析并落盘。

## 为什么这套“魔法”值得学

- 它已经完成了 **52,907** 个资产的标注闭环
- 主线输出字段已经补齐到 100%
- 失败样本不会悄悄消失，而是会以 `raw_output` 形式保留下来，方便重试和修复
- 你既可以本地跑，也可以按 chunk 拆到多机或 DLC 上跑
